## 1. Problem

The test suite leaks lines into the production stable logs in `~/.claude/hooks/`. Verified state of `bulldozer.log` (2026-07-20):

- **≥ 1880 of 2865 lines (65.6%) are test-origin**, in three disjoint classes: 1346 lines with a pytest tmp `project=` path, 462 `event=reconciled` lines (no `project=` field; 448 carry `artifact=test`/`test-artifact`, the rest belong to a 100%-pytest session), and 72 `event=wrapper-fail` lines from one arg-parse test. (An earlier 47% figure counted only the first class.)
- `event=reconciled` and `event=wrapper-fail` as event classes carry **zero / near-zero production signal** (0 and 2 genuine lines respectively).
- The leak is LIVE: fresh test lines on 2026-07-18/19/20, including lines written by the audit itself.

Confirmed leak sites (all: subprocess invoked without a log env override → producer falls back to `$HOME/.claude/hooks/…`):

- `tests/test_verify_audit_findings.py::_verify` — 3 subprocess calls, 0 overrides → the `event=audit` flood.
- `tests/test_update_state.py` — 1 subprocess call, 0 overrides → the `event=reconciled` flood.
- `tests/test_check_round_wrapper.py::TestSkeleton::test_missing_required_args_fails_with_nonzero_exit` — the single unsandboxed call among 30+ sandboxed ones in that file → the `wrapper-fail` flood.
- `tests/test_e2e_facade.py::FacadeProc` — inherits env without forcing `BULLDOZER_CODEX_LOG`; the module-local autouse redirect in `tests/test_codex_facade.py::_redirect_facade_log` does not cover it (historical `simulated spawn failure` lines in `bulldozer-codex.log`, residue closed by e6a5894 but the pattern is one dropped fixture away from returning).

**The attribution problem (R1-F1, blocker-class):** some leaked lines are **byte-identical to genuine production lines**. The missing-args `wrapper-fail` writer emits only empty `round=`/`artifact=`/`reviewer=`/`depth=` plus `exit=`/`reason=` (grep `_bdz_log wrapper-fail` in `skills/check/scripts/bulldozer-round.sh`); facade `FACADE_SPAWN_FAIL` emits only `call=`/`err=`. No content marker can attribute such a line to a test run — attribution must be injected at the SOURCE (§4 D1, session sentinel).

Operational cost: two entire event classes are unusable for mining, and the 33-candidate log audit measured a ~73% false-alarm rate among its raw signals, driven almost entirely by mistaking test-origin lines for production behaviour.

## 2. Goal invariant

> A test run (`pytest tests/`, bare-pytest runner, with or without `-n auto`) appends **zero** lines to any production stable log, and this is **machine-checked on every run** — a future leak fails the suite instead of silently accreting.

Non-goals: changing `lib/bulldozer_log.py` (verified correct — flock-serialized append+rotation, honors overrides at every call site); changing producer LOGIC; cleaning historical pollution (opt-in, §8). ONE narrow amendment (R11-F1): the child-env ALLOWLISTS in `codex_server` and `codex_facade.Worker` gain the 7 `BULLDOZER_*` knob names as forwarded-when-present entries — configuration, not logic; the knobs are not secrets, so the fail-closed property is unchanged. Without it, codex descendants are env-scrubbed past the repair chokepoint and an e2e that asks codex to run a stable-log producer falls back to the real `HOME`.

## 4. Design

### D1 — env redirect + session sentinel at `tests/conftest.py` **module level** (the fix)

At the **top level** of `tests/conftest.py` (not inside a fixture), before any test module is imported:

1. Record the prior value (or absence) of each of the 7 knobs + `CLAUDE_CODE_SESSION_ID` + `BULLDOZER_TEST_SENTINEL` (9 entries) in a module dict.
2. Create one per-process private dir: `tempfile.mkdtemp(prefix="bulldozer-test-logs-")`. Point the 6 file knobs at files inside it and `BULLDOZER_INVOKE_LOG_DIR` at a created subdir.
3. **Session sentinel (R1-F1), regeneration-guarded (R1-F2 r3):** the naive "generate at module level" breaks under xdist — each worker imports conftest itself and would regenerate a DIFFERENT random sentinel. Guarded protocol (R1-F1 r5, third conjunct added at implementation 2026-07-21): ADOPT the inherited `BULLDOZER_TEST_SENTINEL` ONLY when ALL THREE hold — the process is a positively identified xdist worker (`PYTEST_XDIST_WORKER` present in env), the value matches the exact wire form `^PT[0-9a-f]{6}$` (the writer truncates sessions to 8 chars via `_session_token` — an unvalidated longer value would make D2 search for a token that never appears on the wire), AND `BULLDOZER_TEST_SENTINEL_SPAWNER` equals this process's ppid — the pid the regenerating controller records as its own. The third conjunct closes a hole T2b caught live under an `-n auto` outer run: `PYTEST_XDIST_WORKER` is inherited by EVERY descendant of a worker, so a nested pytest spawned FROM a worker masquerades as one by the env-var test alone; execnet spawns real workers as DIRECT children of the controller, so the ppid check disambiguates (pinned by the stale-sentinel T2b test with a never-matching SPAWNER). In every other case — controller, non-xdist run, missing or malformed value — REGENERATE `"PT" + 6 random hex`. In EITHER branch, unconditionally set BOTH `BULLDOZER_TEST_SENTINEL` AND `CLAUDE_CODE_SESSION_ID` to the selected sentinel (a stale inherited guard var alongside a production `CLAUDE_CODE_SESSION_ID` must not leave the two divergent — writers emit the session var, the guard searches the sentinel). Workers inherit the guard var → adopt, never regenerate → one sentinel per run by construction. Every stable-log producer derives `session=` from it (F7), so ANY line a test writes — including the byte-identical `wrapper-fail`/`FACADE_SPAWN_FAIL` shapes — carries the sentinel. Unique per run → a concurrent old-suite run elsewhere cannot false-fail this run's guard.
4. Record `SESSION_START = time.time()` **and the per-file baseline of every production log (`st_ino` + size)** in the same module block (NOT at fixture setup — a collection-time leak must fall inside BOTH the timestamp window and the offset fast-path window; a fixture-time baseline would let the tail-scan start past a pre-fixture leak, R1-F2 r2).
5. **Restore + cleanup via `atexit`** registered in the same block: restore all 9 saved env entries (delete the ones previously absent) and best-effort `shutil.rmtree` the private dir. `atexit` runs on the xdist controller, workers, zero-selected runs, and collection failures alike — a session-fixture teardown covers none of the controller cases (F8, R1-F3). Documented limitation: an *in-process* embedded `pytest.main()` caller sees the redirect until its process exits — accepted (nothing embeds pytest here; CI and dev invoke the `pytest` binary).

**Why module-level, not a fixture (load-bearing, F2):** an autouse session fixture executes at first-test setup — *after* collection has imported test modules. Any in-process import of `cdp.py`, the workflow hook, or `consult_panel.py` during collection would freeze the real default path into their module constants before the fixture ran. Conftest module-level code runs before collection imports, closing the ordering hole for both in-process imports and (trivially) subprocesses, which inherit `os.environ`.

**Why this covers the subprocess leak sites:** every confirmed site today passes `env=None` (inherit) or builds from `os.environ.copy()` (F5) — both inherit the redirect. Going forward, `env=None` stays plumbing-free; sites that MODIFY the env migrate onto `test_env` (D3a), which also starts from the inherited redirect. Per-test explicit `CLAUDE_CODE_SESSION_ID=...` overrides (e.g. `test_drive_invoke_marker`'s `cafebabe99`) are fine — those tests sandbox their writers into `tmp_path` anyway.

### D2 — sentinel-based leak guard (regression tripwire for D1)

Two layers (R1-F2 r4): a session-scoped autouse fixture provides the EARLY start-assert; the AUTHORITATIVE scan runs from a `pytest_sessionfinish` hook in conftest — pytest executes that hook even on zero-selected runs and collection errors (the cases where no fixture ever runs, F8), so a collection-time leak followed by a collection failure is still checked. On offenders the hook prints them verbatim and forces a non-zero exit (loud failure is acceptable here — a leak is an emergency, not a routine assert). The guard core is a **pure function** `scan_for_leaks(log_dir: Path, sentinel: str, since: float, baselines: dict, markers: list) -> list[str]` — target paths AND the per-file `{name: (st_ino, size)}` baselines recorded at conftest module level arrive as explicit parameters (R1-F2 r3: the fast path depends on the baseline, so it is part of the contract, not ambient state), **no env seam** (R1-F6: an env-var seam is an unauthenticated kill switch — if inherited from the outer environment, the guard silently scans the wrong directory). The `pytest_sessionfinish` hook calls it with the hard-coded real dir (`Path.home() / ".claude" / "hooks"`, same convention as F6's existing guard) and the module-level baselines; the autouse fixture carries only the early start-assert; the guard's own unit tests call the function directly with fabricated dirs and baselines.

- **Start assert (fixture setup):** (a) each of the 7 knobs currently points inside the private tmp dir and is non-empty (F11), and `CLAUDE_CODE_SESSION_ID` equals the sentinel; (b) **the three import-frozen constants captured the redirect** — for each of `skills/look/scripts/cdp.py`, `hooks/require-workflow-skill.py`, `skills/consult/scripts/consult_panel.py`: if a loaded instance already sits in `sys.modules` (the collection-loaded one — `test_consult_panel.py` imports its module during collection), assert THAT instance's `LOG_FILE` / `LOG` / `CONSULT_LOG` resolves inside the private tmp; importlib-load by path only as the not-yet-imported fallback (R1-F2 r3: a fresh importlib instance proves nothing about the instance tests actually use); (c) under xdist, the sentinel is identical in every worker AND equals `BULLDOZER_TEST_SENTINEL` — pinned by a subprocess `-n 2` test where each worker records its sentinel to a shared file and the assertions compare all values to the controller's guard var (the adopt-don't-regenerate protocol of D1 point 3 is what makes this hold). Deterministic, no races; self-diagnosing failure messages.
- **Sessionfinish scan (authoritative):** for each of the 6 real production log files, collect candidate lines and assert none is a leak, printing offenders verbatim. Runs from `pytest_sessionfinish` in every process that imported conftest (workers AND controller), with the module-level baselines. A line is a leak iff its timestamp ≥ `SESSION_START - 1s` AND any of FOUR detectors fires:
  1. `session=<sentinel>` — the PRIMARY detector (covers every writer that derives session from env, incl. `update-state` on session-less fabricated state, F10);
  2. `session=cafebabe` — the **reserved test-session id** (covers explicit-session tests and update-state runs on fabricated state that carries a session key, F9/F10 — the R1-F1 "explicit-session leak" closure; D3 forces all fabricated/explicit ids into this reserved value);
  3. a secondary content marker: `pytest-of-it` path, `artifact=test`/`test-artifact`, or `project=` under the private tmp;
  4. `project=`/path value pointing into the private tmp dir.

Scan mechanics (R1-F4):

- **Generation detection via inode, not size:** record `st_ino` (+ size) per file at conftest import. At scan time, if `st_ino` changed → rotation happened → scan BOTH the current file and the `.1` sibling in full (timestamp filter suppresses historical lines). If inode unchanged and size grew → scan from the saved offset (fast path). Size alone cannot identify a generation (a rotated file can regrow past the saved offset).
- **Timestamps are parsed, not compared lexicographically:** parse the leading ISO field with `datetime.fromisoformat`; a naive (legacy-form) timestamp is assumed local. Comparison in epoch terms — robust to mixed-offset forms.
- **Scan under the writer's lock:** take a brief shared flock on the `<log>.lock` sibling (same protocol as `lib/bulldozer_log.py`) while stat+read, so the scan cannot race `os.replace` mid-rotation.
- **Best-effort boundary (documented in the guard's docstring):** TWO rotations of the same log within one pytest run would overwrite `.1` and lose the middle generation (F3). With tests redirected to tmp, real-log growth during a run comes only from foreign writers (~hundreds of lines/day against a 5 MB cap) — double rotation mid-run is not a realistic event; the guard does not chase it.

**xdist correctness:** `pytest_sessionfinish` runs in EVERY worker (each worker is its own pytest session) and in the controller — which finishes last, after all workers. A leak during worker A's tests is therefore caught at latest by the controller's scan; no test runs after that point. Fixtures never execute on the controller (F8), which is exactly why the authoritative scan is a lifecycle hook, not a fixture.

**Closure of the explicit-session hole (R1-F1 r2, replaces v2's "accepted limitation"):** a test may legitimately need a non-sentinel session (asserting on `session=` output, fabricating state.json). Rule: every such site MUST use the reserved id `cafebabe99` (the de-facto convention at all 8 integration-style sites; the three hermetic logging-unit-test literals are allowlisted, F10) — detector 2 then catches any leak from them by construction. D3 enforces the rule structurally; a novel explicit id cannot appear without failing the scan. The remaining theoretical miss — a leak line carrying a FOREIGN production session id — can only come from a fabricated state.json with a non-reserved session, which D3 forbids.

### D3 — structural invariant test with a pinned allowlist (closes the residual bypass class)

The redirect cannot protect a subprocess whose env is **constructed from scratch** without the knobs (fallback → real `$HOME`). One structural test pins the invariant, house-style (cf. `test_no_raw_preslice_at_drift_warn_call_sites`):

The protected set is **8 vars**: the 7 knobs + `CLAUDE_CODE_SESSION_ID`. v3's five static scan classes could not honestly promise completeness (alias/loop-variable dataflow, helper-built shell strings, `env -u` — R1-F5 r3); v4 replaces breadth-of-scan with a **centralized runtime chokepoint** plus two narrow scans:

**D3a — one subprocess-env builder (the enforcement point).** A conftest helper `test_env(drop=(), set_vars=None, unsafe_allow=())` is the ONLY sanctioned way to build a modified env for a subprocess in tests. It starts from `os.environ.copy()`, applies `set_vars`, drops `drop` — and **raises at runtime** if any operation would remove or empty a protected var (directly, via loop variable, or via `set_vars={K: ""}`) unless that var is named in `unsafe_allow` — and `unsafe_allow` itself is validated against a CENTRAL module-level allowlist in conftest (`(var, callsite-file, justification)` tuples): a call from a file not pinned there raises regardless of what it passes (R1-F5 r4: caller-supplied justification alone would let any new test self-authorize). Aliases, loops, and helper indirection are irrelevant: every path reaches the same runtime check. Existing sites migrate in this PR: the conftest `LANE_ENV_VARS` pops (lane vars are unprotected — no `unsafe_allow` needed), `test_drive_invoke_marker` — its intentional DRIVE_LOG-absent fallback routing would be defeated by knob re-injection (R10-F1), so its migration ALSO gives the subprocess a scratch `HOME` (the sanctioned foreign-HOME branch: absent knobs stay absent, the hook still routes through `BULLDOZER_INVOKE_LOG_DIR`, and the fallback path is sandboxed); T6c asserts end-to-end that the migrated test still writes through `BULLDOZER_INVOKE_LOG_DIR`, and the generic `env.pop(k, None)` helper loops.

**D3a-rt — runtime process-creation chokepoint, REPAIR-based (R7-F1 r7/r8, R8-F1 r8/r9, R9-F1 — supersedes the stamp design).** The `subprocess.Popen` wrapper (`subprocess.run` funnels through it) is installed at conftest **MODULE level** (same import-ordering argument as D1; restored by the same atexit handler), so collection-time creations are covered. Validation is **repair, not rejection** — the r9 stamp design failed twice over: production-internal builders (`codex_server`'s fail-closed child env, `codex_facade.Worker`'s spawn env, `consult_panel.run_model`) legitimately construct envs without any test helper, and a stamp certifies a token, not the launch-time contents. The repair rule enforces the actual invariant — *no child of the test process may resolve a stable log into the real `Path.home()/.claude/hooks`* — at the only place it can be guaranteed:

- `env=None` → inherit — but first ASSERT the parent `os.environ` knobs still resolve non-production (R10-F2: an unsanctioned in-process mutation of `os.environ` after conftest import would otherwise ride the inherit branch; violation raises, naming the mutated knob).
- env carries a **foreign HOME** (present and resolving outside the real home) → the child's `Path.home()` FALLBACK is sandboxed, so absent/empty knobs are left alone (the T2/T4 scratch-`$HOME` repro shape keeps its RED premise) — but an EXPLICIT knob resolving under the real production dir outranks the fallback in every producer (`os.environ.get(K) or default`), so such values are still REPAIRED even on this branch (R10-F2).
- otherwise → for each of the 7 knobs that is absent, empty, or resolves under the real production dir, INJECT the session redirect value into a copy of the env (never mutating the caller's dict); all other keys pass through verbatim. A per-test re-point to its own `tmp_path` is non-production → preserved. Production builders need NO changes and NO certification — their real call paths through `codex_server`, `codex_facade.Worker` and `consult_panel.run_model` get the knobs injected and keep every other allowlisted key (the injected `BULLDOZER_*` paths are not secrets, so the fail-closed child-env allowlist property is unaffected).
- a literal `env`+`-i` argv prefix still raises (command-level clearing cannot be repaired).
- **relative paths are unclassifiable from the parent** (post-implementation codex review P2, 2026-07-21): the child resolves them against ITS cwd — a relative knob value (`.claude/hooks/bulldozer.log` + `cwd=$HOME`) or a relative `HOME` can land IN the production dir while the parent-side `resolve()` (against pytest's cwd) reads non-production. Rule: a relative `HOME` never qualifies as the foreign-HOME sandbox, and a relative knob value is ALWAYS repaired. Both pinned by RED-proven tests.

`test_env` remains the ergonomic builder (protected-drop runtime check against the central allowlist, F11 empty-value check) but no longer emits a stamp; `scrub=True` products are repaired like any other env, so even a deliberately minimal child that unexpectedly launches a stable-log writer lands in tmp (the R9-F1 scrubbed-writer hazard dissolves).

**Threat model (declared boundary):** D3's layers defend against ACCIDENTAL misconstruction by future test authors. Deliberate evasion (e.g. `bash -c "env -i …"` nested inside a shell string, direct `os.posix_spawn`) is out of scope by declaration — any lint/wrapper is evadable by a determined author; code review and D2's runtime scan remain the nets for what carries attributable content. Both named exotic shapes have ZERO instances in the current tree (verified: the `**kw` hits in tests are mocks/frame-builders, the `env -i` hit is a string fixture).

**D3b — two narrow static scans** (house-style, cf. `test_no_raw_preslice_at_drift_warn_call_sites`). Both scans consult the ONE central allowlist shared with D3a (entries carry justifications); scan 1's only legitimate entries are env-forwarding helper definitions (their internal build must go through `test_env`) — plain test callsites are never allowlisted:

1. **Env provenance — kwarg-anchored (R1-F5 r4/r5/r6; r12 implementation refinement):** the scan is anchored on the **`env=` keyword argument itself**, not on the callee: ANY call expression in `tests/*.py` carrying `env=` must pass `None` or a `test_env(...)` call — plus ONE additional accepted form added at implementation to match §7's own rollout shape (`env=os.environ.copy()+updates` → `test_env(set_vars=…)` bound to a local): `env=<name>` where the enclosing function binds `<name>` EXACTLY ONCE and that binding is `<name> = test_env(...)`; any other or additional binding (rebinding, parameter, loop target) is a violation. Post-build dict tweaks of such a name are permitted — protected-var damage after `test_env()` is the RUNTIME chokepoint's job (the declared division of labor). Because the anchor is the kwarg, callee identity is irrelevant — `subprocess.run`, `sp.run` after `sp = subprocess`, `run = subprocess.run; run(...)`, and any future wrapper are all caught identically; the r5 canonical-import rule is thereby superseded and dropped (no alias/rebinding analysis needed at all). An `os.environ`-derived expression, a from-scratch dict literal, or a bare `os.environ.copy()` expression each fail, naming file:line. Test helpers that forward an env to `Popen` (e.g. `FacadeProc`) either stop accepting caller env or appear in the central allowlist with the requirement that their INTERNAL build goes through `test_env`. Non-subprocess helpers already use distinct kwarg names (`extra_env`, `env_override`) — verified, no false-positive surface. Shell-string mutation of protected vars (`unset X` / `X=` / `env -u X` inside command strings) is scanned best-effort as a tripwire — with D3a as the chokepoint it is defense-in-depth, not the primary mechanism.
2. **Explicit session ids (feeds D2 detector 2; closes R1-F1 r3):** any assignment of `CLAUDE_CODE_SESSION_ID`, any `"session"` key in a fabricated state.json fixture, AND any explicit `session=` argument to `append_line` / the CLI shim in tests must use the reserved `cafebabe99` — a novel literal fails unless allowlisted. Initial allowlist (all hermetic — they write only to explicit tmp paths): `tests/test_bulldozer_log.py` (module-scoped: `_session_token` unit tests use adversarial ids, `monkeypatch.delenv`/`env.pop` of the session var, and direct `append_line(session=…)` calls) and the one adversarial-session site in `tests/test_consult_panel.py`.

**Runtime-vs-structural division of labor (honest scope):** D2's runtime detectors attribute leaks carrying the sentinel, `cafebabe`, or a content marker. A leak with a NOVEL session id is *prevented* by D3b-2 at the source, not *detected* at runtime — there is no content signal to detect it by. ## 8. Historical pollution — RESOLVED as archive-rotation (option C), 2026-07-21

The v12 draft of this section proposed a filter-in-place cleanup (`cp` backup → class filter → atomic `mv`). **That plan was REFUTED post-implementation** by a unanimous three-reviewer consultation (consult `--panel --repo`: GPT + Grok; separate codex xhigh run — all recommended archive-rotation instead):

- filter-in-place races live writers (a line appended between filter and `mv` dies in the replaced inode; a concurrent 5 MB rotation is worse) — safe only under a held `LOCK_EX`, and still lossy;
- the `wrapper-fail` class drop destroys 2 genuine production lines; `event=reconciled` is a legitimate production event (its 0-production count was a corpus fact of 2026-07-20, not semantics);
- "leave as is" was no safer: the writer's single-slot `.1` rotation destroys the mixed generation within two rotations;
- the audit counts had already gone stale (2865 → 2929 lines) — a blind class filter would have eaten post-audit production lines.

**Executed 2026-07-21 (approved by user):** under the writer's own `LOCK_EX` on `bulldozer.log.lock` — recount → no-clobber `os.rename` of the untouched log to `bulldozer.log.pre-357-isolation` (deliberately NOT `.1`, which the writer clobbers) → fresh empty log with the original mode → fsync file+dir → unlock → `event=log-archived` audit line via the canonical helper → sibling `.manifest.json` (cutover ts, inode, per-class counts, sha256 of raw bytes) → gzip after a checksum-stability probe.
