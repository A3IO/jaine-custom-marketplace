# Bulldozer Plugin

Adversarial review (`/bulldozer:check`) + visual browser verification (`/bulldozer:look`) + agent-driven product testing (`/bulldozer:drive`) + lightweight design consultation (`/bulldozer:consult`) + multi-agent Workflow orchestration doctrine (`workflow-swarms`).

## Skills

| Skill | Command | What it does |
|-------|---------|-------------|
| check | `/bulldozer:check` | Adversarial review loop with external AI reviewer (model selection → `-c` reasoning overrides → structured ledger). For artifacts on disk. |
| look | `/bulldozer:look [URL] [task description]` | Browser automation via CDP, AppleScript, macOS native |
| drive | `/bulldozer:drive [URL] [test task]` | Product testing on isolated Chrome-for-Testing lanes with a verify-core (navigate-wait, console-gate, stability-window assert, trusted clicks, bound screenshots); autonomous / co-pilot modes; opt-in cookie-seed auth. SP2 (#164 epic). |
| consult | `/bulldozer:consult [design question]` · opt-in `--panel [--repo PATH] [--verdict]` | Lightweight stateless codex consultation for abstract design Q&A (inline text, no artifacts), process-isolated from an empty tmpdir. Opt-in `--panel` runs codex+grok+agy in parallel for multi-model find-holes (`skills/consult/scripts/consult_panel.py`); `--repo` lets them read real code (informed review). |
| workflow-swarms | (doctrine skill — auto-triggers on "build a workflow" / "fan out agents" / ultracode) | Per-role model routing (haiku breadth / sonnet judge / explicit opus synth) + throttling doctrine for multi-agent Workflow-tool swarms, and the recall-preserving swarm→rank→verify-all find-holes pattern with a bounded stopping-rule. Ships WITH a matching **`require-workflow-skill`** PreToolUse(Workflow) guardrail hook (`hooks/require-workflow-skill.py` + `hooks/hooks.json`, `${CLAUDE_PLUGIN_ROOT}`-portable) — **ADVISORY by default** (injects the doctrine on every Workflow call); **DENY is OPT-IN** via the `BULLDOZER_ENFORCE_WORKFLOW_ROUTING` env var, so installing bulldozer never surprise-blocks a consumer's workflows (panel verdict 2026-06-14: an opinionated heuristic guardrail must not be imposed by default). |

## Architecture: /look

`cdp.py` — CDP commands across 3 communication channels:

| Channel | When | Commands |
|---------|------|----------|
| CDP WebSocket | websocket-client available (bundled) | All (see `COMMANDS` dict in cdp.py — 23 now) |
| AppleScript + DOM injection | websocket missing | js, title, click, fill, wait, navigate, reload, viewport |
| macOS native | screenshot without websocket | screenshot only |

JAINE Browser = separate Chrome instance on CDP port 9333.

**Lanes (/look-v2, 2026-06):** `launch.sh` is parameterized via `CDP_PORT` / `LOOK_PROFILE_DIR` / `LOOK_HEADLESS` — the daily browser (port 9333, daily profile) and isolated test lanes (non-9333 port + own profile dir) coexist without fighting over state. **Daily-profile gate (#160):** the daily profile is bound to port 9333 and to nothing else — a non-9333 lane whose `LOOK_PROFILE_DIR` realpath-resolves to it is refused UNCONDITIONALLY (no flag needed to trip it). The lane's restart `pkill`s by `--user-data-dir`, not by port, so an ungated flat lane on the daily profile killed the user's live browser; the three opt-in gates below each caught it, the flagless path did not. Opt-in `--insecure` (or `LOOK_INSECURE=1`) adds `--disable-web-security` for trusted-LAN / `file://` testing, gated **fail-closed to isolated lanes only**: non-9333 port + explicit non-default `LOOK_PROFILE_DIR` (realpath-canonicalized, alias-proof). Full contract: `skills/look/SKILL.md` → "Web-security lane". **Automation lane (SP1, #164):** opt-in `--automation` / `LOOK_AUTOMATION=1` — pinned Chrome for Testing binary by default (`/0/.jaine/.browser/cft/current`, installed/pinned ONLY by `skills/look/scripts/update-cft.sh`), `--enable-automation` + `--use-mock-keychain`, temp per-port drive-profile (`$TMPDIR/jaine-drive-<port>`), gated **fail-closed**: non-9333 port + profile that does not resolve to the daily profile. `CHROME_APP_NAME` threads the AppleScript/Quartz app name into cdp.py (defaults: stock `Google Chrome`; automation `Google Chrome for Testing`) — every cdp.py call against a CfT lane carries BOTH `CDP_PORT` and `CHROME_APP_NAME`. Full contract: `skills/look/SKILL.md` → "Automation lane"; empirical basis: `docs/superpowers/analysis/2026-06-05-sp1-cft-empirical-findings.md`. **Cert-pin lane (dogfood #1, PR #169):** opt-in `--cert-spki=<PIN>` / `LOOK_CERT_SPKI` appends `--ignore-certificate-errors-spki-list=<PIN>` to Chrome argv — pin-only TLS bypass for self-signed HTTPS LAN targets (typical home-lab); same fail-closed gate as `--insecure` (non-9333 + provably-isolated profile); `--automation` temp profile satisfies it. Malformed pins rejected fail-loud. Full contract: `skills/look/SKILL.md` → "Cert-pin lane".

**Also in /look-v2:** sub-B — `window bounds` answers over CDP (`Browser.getWindowForTarget`, headless-capable, stdout contract `left,top,width,height`); sub-C — global `--target SEL` pins every command in a call to one tab (full id / 12-char prefix / url substring; ambiguous or unknown → fail-loud; websocket channel required). Command inventory lives in the `COMMANDS` dict in cdp.py; look-facing commands are listed in look SKILL.md Quick Reference.

**Design principle:** cdp.py is used by JAINE (Claude Code agent), not a human. Design accordingly:
- Explicit flags (`--js`, `--full-page`) over heuristic auto-detection
- Parseable, stable output format over pretty formatting
- No silent fallbacks — warn on stderr when requested behavior degrades
- SKILL.md = API docs for the agent; if a capability isn't described there, JAINE won't use it

## Architecture: /drive (SP2, #164 epic)

`skills/drive/SKILL.md` — agent-driven product testing on isolated CfT lanes (ports 9340-9349 interactive; the daily 9333 browser is structurally unreachable — launch.sh gate + script guards). The verify-core is **opt-in extensions of the shared cdp.py engine** (spec §4.1 — commands differ in SKILL.md defaults, not in the engine; /look's no-flag defaults byte-identical):

| Primitive | Surface | Contract |
|---|---|---|
| navigate-wait | `navigate URL --wait [load\|domcontentloaded\|networkidle] [--expect-url S] [--timeout S]` | blocks on `Page.lifecycleEvent` filtered by OUR loaderId (prior-page race closed); prints final URL + `loader=` token; `NAVIGATE_FAIL`/`NAVIGATE_URL_MISMATCH` + exit 1 |
| console-gate | `console --gate` | exit 1 on any error/exception; FAIL line carries the per-leg breakdown (`N (X exception(s), Y console, Z log)`). Three-channel contract: **exceptions retro** (replayed to late subscriber) + **console.* live 3s window** (call the gate right after the action; retro console.* replay is a fragile activation quirk — NOT promised) + **Log domain live** (CORS/CSP/net::ERR_* surface ONLY as `Log.entryAdded` — code-review pack A, empirically confirmed). Buffer clears per-navigation. Empirics: `docs/superpowers/analysis/2026-06-05-sp2-console-gate-verification.md` |
| assertion | `assert [--js] EXPR_OR_SEL [--visible\|--actionable] [--stable MS] [--timeout S]` | condition must hold CONTINUOUSLY for --stable ms; flap diagnostics distinguish flaky from absent; `--actionable` = visible+enabled+hit-test with cmd_click's scrollIntoView parity |
| trusted-click signal | `click SEL --require-trusted` | refuses the untrusted `el.click()` fallback (`CLICK_REQUIRE_TRUSTED_FAIL` + exit 1, NO click) — R2-U |
| screenshot-binding | `screenshot F --bind` | second stdout line `BIND url=… loader=… t=…`; compare `loader=` with navigate's token to detect stale captures |
| cookie-seed | `skills/drive/scripts/cookie_seed.py --domains … --to-port …` | two-port script (cdp.py stays single-port): Storage.getCookies(9333) → dot-anchored domain filter → setCookies(lane); never seeds INTO 9333; counts-only output |

Modes (§4.4): autonomous (headless, default) / co-pilot (headful, main-session-only — **subagents are always autonomous**, hard-coded in delegation prompts). Circuit-breaker: max 3 fix-verify iterations, then honest STOP. Engine boundary (SP0 bounded-both): Playwright NOT built — a demonstrated cdp.py wall files an issue.

**Ephemeral lanes (SP4):** subagent delegation uses `CDP_PORT=0` — the OS assigns the
port, launch.sh derives a unique mktemp profile (`jaine-drive-eph-XXXXXX`), and prints a
4-line contract (`CDP_PORT/LANE_PROFILE/LANE_KILL_MATCH/LANE_BROWSER_BIN`). The unique
profile IS the ownership token (holes R1-H/R2-R closed structurally — no allocator, no
locks); teardown by the launcher-escaped `LANE_KILL_MATCH` can only kill its own browser.
Gated to `--automation` + launcher-owned profile, fail-loud otherwise. Delegation
protocol: `skills/drive/SKILL.md` → "Subagent delegation". Calibration assets:
`skills/drive/data/calibration-manifests.json` (frozen oracles) +
`skills/drive/scripts/grade_run.py` (external grader) + `tests/fixtures/calibration/`.

## Testing

### Test suites

These skill domains — `/look` (browser/CDP), `/drive` (verify-core + cookie-seed), `/check` (review composer wrapper + parser + state), and `/consult` (panel orchestrator + wrappers + parsers + classifier) — are tabled below; alongside them the suite carries the MCP-server tests (`test_codex_mcp_v2.py`), the facade multiplexer (`test_codex_facade.py` offline against scripted fake workers + `test_e2e_facade.py` slow, live against the real engine — self-skips without codex), and offline structural/hook guards (`test_workflow_swarms_skill.py`, `test_require_workflow_skill.sh`, `test_plugin_structure.sh`, `test_ax_renderer.py`). Live inventory: `ls tests/`; live count: `pytest tests/ --co -q | tail -1`.

| Domain | Files | Type | External dep |
|--------|-------|------|--------------|
| `/look` | `test_cdp.py`, `test_launch.py`, `test_ax_renderer.py`, `test_e2e.py`, `test_e2e_cft.py` | structural + behavioral | `test_e2e.py` → JAINE Browser; `test_e2e_cft.py` → pinned CfT (self-skips if not installed) |
| `/drive` | `test_e2e_drive.py`, `test_e2e_lanes.py`, `test_cookie_seed.py`, `test_drive_skill.py`, `test_grade_run.py` | behavioral (CfT lane) + offline unit/structural | `test_e2e_drive.py` → pinned CfT via `cft_browser` (self-skips); `test_e2e_lanes.py` → pinned CfT, self-launches ephemeral lanes (self-skips); cookie-seed e2e launches a second transient lane on 9362 |
| `/check` | `test_check_round_wrapper.py`, `test_parse_ledger_patch.py`, `test_skill_prompts.py`, `test_verify_audit_findings.py`, `test_update_state.py`, `test_check_pipeline_integration.py`, `test_log_round_bash32_compat.py`, `test_check_e2e.py` | structural + behavioral | `test_check_e2e.py` → codex |
| `/consult` | `test_consult_panel.py` | structural + behavioral (injected runner; one real-subprocess reaping test) | live `--panel` e2e is dogfood-only |

Most are offline structural tests (fast). The external-dep e2e tests **self-skip** when their dep is missing — EXCEPT `test_e2e.py`. The CfT-based ones (`test_e2e_cft.py`, `test_e2e_drive.py`, `test_e2e_lanes.py`) `pytest.skip` when CfT is not installed (`update-cft.sh`; `test_e2e_cft.py` auto-launches its own pinned-CfT lane on `DRIVE_TEST_PORT`), and the codex tests (`test_check_e2e.py`, `test_codex_mcp_v2.py` slow e2e) skip via `skipif(not codex)` — all safe in any run. **`test_e2e.py` (JAINE Browser) is the exception:** no `slow` marker, and its `jaine_browser` fixture calls `pytest.fail()` (not skip) if Chrome won't launch — so a bare `pytest tests/` on a no-Chrome machine fails there. Note also that `slow` is **NOT** deselected by default (no `addopts`/pytest.ini; conftest.py says pass `-m "not slow"` for fast-only runs), so the codex slow e2e DO run by default when codex is present.

### Running tests

**Runner: bare `pytest` (homebrew python3), NOT `uv run pytest`** — this plugin has no
`pyproject.toml`, so `uv run` builds an ephemeral env WITHOUT PyYAML and the check-wrapper
suites fail with 56 spurious `parse-ledger-patch.py requires PyYAML` errors (identical on a
clean `bulldozer/main` baseline — the house `uv run pytest` doctrine applies to uv PROJECTS).

```bash
# Structural tests (fast, offline)
pytest tests/test_cdp.py -v

# E2E tests (auto-launches JAINE Browser if not running)
pytest tests/test_e2e.py -v

# All tests
pytest tests/ -v
```

### Test pages

`tests/fixtures/test-page.html` — deterministic HTML with known selectors for each /look command. `tests/fixtures/drive-page.html` — dynamic page for the SP2 verify-core (async element, flapping element, delayed-enable, occluded + below-fold targets, mid-flow error buttons). Both served by `conftest.py` on a random port during e2e runs.

### Adding new commands — MANDATORY

Every new `cmd_*` function in `cdp.py` MUST have:

1. An entry in `COMMANDS` dict
2. A structural test in `test_cdp.py` (function exists + registered)
3. A behavioral e2e test in `test_e2e.py` (look commands) or `test_e2e_drive.py` (verify-core) — against a real browser
4. A test element in `test-page.html` / `drive-page.html` if the command interacts with DOM

No command ships without all 4.

## Architecture: logging (`lib/bulldozer_log.py`)

All stable-log writers migrate onto one shared helper (#322): canonical line grammar `{ts} | event= | session= | k=v…` (ISO ts with colon offset, token-normalized event/keys, sanitized values, 5MB rotation, best-effort + one stderr warning per process). CLI shim for `.sh` writers: `python3 lib/bulldozer_log.py <log> <event> [k=v …]` (always exit 0). Spec: `docs/superpowers/specs/2026-07-11-bulldozer-log-grammar-design.md`. Migrated (#322 PR1–PR6): cdp.py `log()` (adds `port=`/`target=`; env override `BULLDOZER_LOOK_LOG`; D2 redaction — JS exprs log `expr_len=`/`expr_sha=`, URLs log origin+path with `?<redacted>` marker, never query/fragment/userinfo), check wrapper/log-round/update-state (`wrapper-fail`/`round`/`reconciled` + `pivot` on exit 10), verify-audit-findings (`audit` — E1 proposed vs survived), drive launch.sh + cookie_seed, hooks log_skill_invoke + require-workflow-skill (`require-workflow-skill.log` migrated YAML→pipe-KV, decisions carry `project=`/`session=`). **All ACTIVE producers are canonical since #334** (closed the #322 "53/53" overstatement): the MCP server's `_drift_warn` is now a thin adapter over `append_line` (event=/session=/offset-ts; `acc` keeps the ORIGINAL detail, only the durable copy is URL-redacted, type-unconditionally — a wire dict can't smuggle a URL; helper unavailable → warn once + drop, never a legacy fallback), consult's `_log_completion` and the SKILL.md inline flow (CLI shim, `${BULLDOZER_CONSULT_LOG:-…}` override) emit `event=consult-complete`. **Miner transition:** history + un-restarted servers still hold legacy lines — detect per line (segment 2 `event=` or positional), same event tokens both shapes, legacy `WARNING` bare tail → `msg=`, legacy generic third segment → `detail=`, missing-session sentinel + naive-ts rules and per-producer cutovers in README `## Log Format`. **Redaction** covers look (D2), codex (all `_drift_warn` values) and facade (`err`/`reason`/`detail`/`msg` only — correlation ids verbatim); paths visible, bare tokens/malformed-whitespace URIs undetected, markers may truncate on very long values (secret removed before truncation). The single truncation point is the helper's `_value` cap — no writer pre-slices (pinned by `test_no_raw_preslice_at_drift_warn_call_sites`). Contract test over the REAL producers: `tests/test_log_grammar_contract.py`. Consult's codex legs run OUTSIDE the MCP bridge (F1) — codex failures there appear only in `bulldozer-consult.log`, never as bridge `TURN_ERROR`.

## Architecture: /check

Each round runs through the composer wrapper `skills/check/scripts/bulldozer-round.sh` (PR #109 / #110): it invokes codex, parses the verdict via `parse-ledger-patch.py`, calls `log-round.sh` (writes `state.json` + `bulldozer.log`), renders the trajectory (`render-trajectory.py`), and emits pivot signals (`emit-pivot.py`) — behind a partitioned exit-code contract (`0` ok, `2-5` parser, `10` pivot, `11` manual-extraction, `64/70/71` wrapper). Depth params (max_rounds, reasoning, ephemeral, prompt prefix) come from `skills/check/data/depth-config.json` — single source, mirrored by the SKILL.md "Depth Levels" table (`TestDepthConfigContract` guards drift).

Codex reasoning via `-c` overrides (codex 0.135.0; named profiles still unsupported):
- quick: `-c model_reasoning_effort=medium --ephemeral` + prompt `SKIP SKILLS.`
- standard/exhaustive: `-c model_reasoning_effort=xhigh`

Inter-round context: structured `review-ledger.yml` (cumulative, append-only) + full previous verdict as appendix. Codex outputs `LEDGER_PATCH` YAML block at the end of each verdict — Claude applies it to the ledger.

Pivot triggers (exit 10): flat `ROUND >= max_rounds && verdict != GO`, OR the B6 calibrated early-pivot (#128: `depth == exhaustive` + `round >= 5` + `verdict != GO` + mean-last-3 findings `>= 3.0`). The exit-11 manual-extraction caller protocol mirrors both (SKILL.md Step 7).

**CRITICAL:** Codex exec runs in FOREGROUND only. `-o` verdict file is written last — background + polling causes false truncation diagnosis.

E1 (#94): a per-round read-only `consistency-auditor` agent + `verify-audit-findings.py`
(quote-presence anti-hallucination) pre-cleans doc artifacts before each codex round;
soft-enforced (SKILL Step 1.7 + structural test, no `bulldozer-round.sh` change). See
`docs/superpowers/specs/2026-06-01-e1-pre-review-consistency-audit-design.md`.

## Feedback Protocol

Before working on skill improvements, check for feedback issues from other JAINE sessions:

```bash
gh issue list --repo A3IO/jaine-plugins --label feedback,bulldozer --state open
```

Feedback issues are created by JAINE-consumer sessions that encountered friction while using bulldozer skills. Each issue follows a structured template: what was attempted, what went wrong, workaround used, and plugin version.

When fixing a feedback issue:
1. Read the issue body for reproduction context
2. Fix the skill/code/documentation
3. Refresh consumer's plugin cache (`jaine-sync plugins update` or `rm -rf ~/.claude/plugins/cache/jaine-custom/bulldozer/`)
4. Close the issue with a reference to the fix commit

**CRITICAL:** Step 3 prevents stale cache — the root cause of false positives in issue #46 where 3/6 feedback items were invalid because JAINE-consumer was running an old plugin version.

## Versioning

`plugin.json` version auto-bumps on every merge to `bulldozer/main` via the `auto-calver` post-merge hook. Format: `YYYY.MM.DD` (first merge of the day) → `YYYY.MM.DD.N` (subsequent merges same day). **Do NOT bump manually** — it causes double-bump (your bump + auto-bump = `.1` suffix for a cosmetic-only PR).

## Architecture: skills-only

Plugin uses `skills/` directory exclusively. No `commands/` directory — per Claude Code docs, commands and skills are the same mechanism, and having both with the same name causes one to be silently dropped. Each `/bulldozer:*` invocation loads `skills/*/SKILL.md` directly.

## Architecture: consult vs check (issue #96)

`consult` and `check` solve overlapping problems with disjoint scopes:

| Aspect | `bulldozer:check` | `bulldozer:consult` |
|--------|-------------------|---------------------|
| Input | File/dir/diff on disk | Inline text in conversation |
| State | `.bulldozer/<session>-<artifact>/` (per-review dir, ledger, state) | None (each invocation independent) |
| Codex sandbox | Read-only at `-C $PROJECT_ROOT` | Read-only at empty `/tmp/bulldozer-consult-$$/` |
| Codex isolation flags | `--ephemeral` (quick only) | Always `--skip-git-repo-check --ignore-user-config --ignore-rules --ephemeral` |
| Verdict format | LEDGER_PATCH YAML in clean `-o` file | Inline prose + GO/NO-GO/MINOR-FIXES + basis sentence, parsed fail-closed |
| Multi-round | Reviewer sees ledger + previous verdict as appendix | Each round independent; user re-prompts manually |
| Empirical verification | Required (`/receiving-code-review` discipline) | Not applicable — codex has no file access |
| Per-round cost | ~30-80s, ~50-100K tokens | ~4-15s, ~5-15K tokens |

**Routing rule (claude-side, enforced by pre-flight in consult Step 2):** if user's prompt mentions any artifact (file path, `.md`/`.py`/etc., "see specs/X", "attached"), redirect to `check`. Otherwise consult.

**Escalation rule** (consult Step 7): if `round_count >= 3` AND last 2 verdicts contain NO-GO, prompt the user to consider `/bulldozer:check`. User decides — we do NOT auto-invoke.

**Panel mode (`--panel`, opt-in, 2026-06-02):** `skills/consult/scripts/consult_panel.py` runs codex+grok+agy in parallel for multi-model find-holes (~50% of findings unique to one model; verdict diversity ≈ 0, so panel is for holes, not GO/NO-GO). (`agy` = Antigravity CLI / Gemini models; replaced the retired gemini CLI, #189.) `--repo <path>` = informed mode — the **deliberate exception to the routing rule above**: the three models read real code (split-test 2026-06-02: informed ≫ isolated for repo-specific questions, tie for abstract). grok hard-no-read proved unachievable on macOS (sandbox governs write/network, not read; `--disallowed-tools` is whack-a-mole) → all three are soft-no-read (empty cwd + prompt). **All three run on the REAL HOME now (#189):** codex isolates via flags (no HOME trick); **grok** via `--no-memory`/`--no-subagents` — a HOME-override sandbox broke grok's `--repo` tool-worker auth (`Auth(AuthorizationRequired)` → grok cancelled on *every* informed run) and was leaky anyway (grok wrote to the real `~/.grok` regardless); real HOME → grok survives 3/3, verified through the panel. **agy** is keychain+OAuth-bound (no copyable token to sandbox); non-interactive `-p` (stdin=DEVNULL → onboards an unknown repo without OAuth, starts no MCP). **Read-only via PreToolUse hook (#189):** `agy --print` AUTO-ACCEPTS every tool (verified no flag/config disables it — not dropping `--dangerously-skip-permissions`, not `--sandbox`, not `autoAccept:false`, not deny lists; print mode can't prompt). The deterministic gate is a **fail-closed** PreToolUse deny hook: the agy leg runs with cwd = a temp dir seeded with `.agents/hooks.json` whose hook ALLOWS only an EXACT set of known read tools (`view_file`/`list_dir`/`read_file`/`grep_search`/… — `view_file`+`list_dir` empirically confirmed) and DENIES everything else — any unlisted/mutating/command-exec tool AND any malformed input → `{"decision":"deny"}` (the earlier substring blocklist let `save_memory`/`shell`/`exec`/`save_file`/malformed-stdin through, #189 code-review); the repo is read via `--add-dir`, never as cwd, so a denied write can't touch it. Reads allowed → review still works. agy persists each call's prompt+response in a per-call `brain/<conversationId>/` session dir (plaintext transcripts — verified by marker probe) + a `conversations/<id>.db`. For statelessness the run injects a unique NONCE into agy's prompt; `_run_one` snapshots brain/ BEFORE the run and afterward deletes only NEW UUID-named dirs whose transcript carries the nonce + `conversations/<id>.db*` — a concurrent agy session (the user's visual Antigravity app) creates a new dir WITHOUT our nonce, so it is never swept (id-via-hook capture failed in the panel-default isolated mode — agy makes ZERO tool calls there, so the hook never fired and the transcript LEAKED until the nonce fix; id is UUID-validated, glob anchored to `<id>.db*` so a prefix-sibling is never swept, #189 code-review). The panel does NOT write `cache/projects.json` (it accumulates a harmless stale temp-cwd entry per run). Model overridable via `BULLDOZER_AGY_MODEL`. Design + empirical basis: `docs/superpowers/specs/2026-06-02-consult-panel-design.md` (§8 = implementation deltas + 2-round dogfood). Post-ship hardening (#142): per-model `_MODEL_SPECS` registry + unified `wrap()` collapse the per-model/per-mode duplication; summarizer delimiter carries a per-call nonce (no boundary spoofing); `run_model` reaps the whole process group on timeout (no orphaned helpers). agy prints plain text (parser = `parse_codex`). Informed find-holes uses BEHAVIORAL wording (NOT "holes/bugs/vulnerabilities") — trigger words trip Gemini's safety refusal on security-flavoured code (proven on an auth file: trigger framing → refused ×2; behavioral → full review); the no-`write_file` clause stays (agy can also save findings to a file and return empty). The `_parse_json_field` three-way "empty response" sentinel is now grok-only (the old gemini-CLI `write_file` empty-response bug it was built for is gone with that CLI — `docs/superpowers/specs/2026-06-03-consult-gemini-write-file-design.md`, historical).

**REMOVED features** (validated against shipping by 3 of 4 independent codex dogfood runs):
- Persistent mode (`codex exec resume`) — data retention risk, stale context contamination, 2× implementation surface. Users wanting continuity copy prior verdict text into a new prompt.
- Session log with prompt content — only metadata in `bulldozer-consult.log`. Raw prompts and verdict bodies are not persisted.

## Architecture: codex facade multiplexer (mcp/codex_facade.py) — #344

**WIRED — the plugin DEFAULT since 2026-07-18**: `.mcp.json` points at `codex_facade.py`. Flipped after a 3-day dogfood bake-in on a dev registration (129 calls, ~19 sessions, **1 `TURN_ERROR` (upstream model-at-capacity, not a bridge fault), 0 `FACADE_SPAWN_FAIL`** — the facade-scoped health metric; 122 facade `TURN_OK` vs 54 legacy; live probes: park→`codex_approve`→resume, native dialog ×27, interrupt, Q1-parallelism, idle-reap. NB when mining: 2 of the 3 post-flip `TURN_ERROR` total are LEGACY-format lines — an `event=`-token histogram undercounts them, see README § Log Format). `BULLDOZER_FACADE_OFF=1` `os.execv`s the legacy single bridge in place (byte-identical path) — the kill switch works even if the facade is broken.

ONE registered MCP server fronting a LAZY pool of workers; each worker = the **UNCHANGED** `codex_server.py` as a subprocess speaking the same NDJSON MCP over pipes, so the whole year of approval/interrupt/park/dialog hardening ships inside every worker. Live-proven: two concurrent `codex_run` turns through one facade OVERLAP — cost 11.6 s + 13.2 s, **wall 13.3 s = max, not the 24.8 s sum** (both `cold_spawn`); through the legacy bridge the second call hits the busy guard (`tests/test_e2e_facade.py`). The **ONE** engine touch is additive and default-off: `_drift_warn` appends `worker=N` when `BULLDOZER_WORKER` is set.

**Idle-timeout heartbeat (2026-07-19):** CC ≥ 2.1.203 aborts a stdio MCP tool call after **30 min with no response/progress frame** (`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT`, **milliseconds** — default 1800000 ms = 30 min; backgrounded and subagent calls NOT exempt; on abort CC tells the server NOTHING — live incident 2026-07-19: a 38.7-min xhigh `codex_run` was killed client-side at exactly 1800 s while the worker ran on to a thrown-away `TURN_OK`). The facade's housekeeping tick now emits `notifications/progress` with each in-flight call's own `progressToken` every 15 s (`heartbeat_inflight` — covers queued, dispatched and approve-resumed calls; stops on reply/cancel/worker death; no token in the request → no beats). Empirical: CC sends `_meta.progressToken` with every `tools/call`, and a progress frame resets the idle timer (verified with a 30 s idle cap: silent 70 s tool died at 30 s, the same tool with 10 s beats survived; through the REAL facade an 84.6 s xhigh turn survived a 30 s cap end-to-end). The legacy single bridge (`BULLDOZER_FACADE_OFF=1`) has NO heartbeat — turns silent >30 min die there; use the facade or raise the env.

**readOnlyHint (2026-07-18):** the facade stamps MCP `ToolAnnotations` `readOnlyHint: true` onto `codex_review`/`codex_info` in its `tools/list` reply (`_annotated_tools`; the engine's `TOOLS` stay unhinted — workers ship unchanged; `codex_run`/`codex_approve` can mutate and stay unhinted). Empirical payoff (CC 2.1.214, `claude -p` vehicle, 2/2 vs 2/2 control): two `codex_review` tool_use blocks in ONE assistant message dispatch in **PARALLEL** when hinted (`FACADE_DISPATCH` delta ≤1 s, workers 0/1, overlapping `TURN_OK`, wall = max) — unhinted, the client holds the second `tools/call` until the first result returns (wall = sum). Consequence: **the MAIN session can fan out reviews from one message** — subagents are needed only for `codex_run` fan-out. Hint scope (documented won't-fix, flip-review round 2): per the MCP spec annotations are hints, not guarantees — outside the hint sit external write-capable MCP servers a caller explicitly enables (`mcp:"all"`/subset) and codex's bundled `computer-use` (undisableable, #204); neither hazard is CREATED by the hint (review concurrency was already structural via the scheduler + the subagent recipe; prompt-injection is outside the threat model — LOCAL single-user, #277).

**Scheduler (§3.2 — correctness over raw parallelism).** Admission and PLACEMENT are one atomic step (the `Scheduler` calls the facade's `place_fn`, so capacity IS the pool's real worker count — no parallel accounting to drift). Serialization rules: writable-root conflicts (equal / ancestor / descendant, **case-insensitively** — the default macOS volume aliases `/Repo` and `/repo`); `danger-full-access` = global write lock; per-worker private `$TMPDIR`; one in-flight turn per thread; **approval-capable = effective `approval_policy != "never"`** — such a turn serializes AND takes the global writer lock (a mid-turn `fileSystem` grant can cover ANY root, #272); **sticky thread widening** — once a thread has run an approval-capable turn it stays a global writer even on a later explicit `never` (a session-scope grant outlives the turn, and in #340 dialog mode the reply never transits the facade, so grants are unobservable). The parallel class is structural: the facade **injects `approval_policy: "never"` AND `sandbox: "read-only"` into every `codex_review` dispatch** (the engine's `run_args = dict(args)` passes them through; the sole exception to verbatim forwarding — a smuggled `sandbox:"workspace-write"` would otherwise reach `thread/start` and contradict both `readOnlyHint` and the always-parallel review class). Queued calls are re-classified at DEQUEUE (their thread may have been widened/re-rooted by the call ahead). A **cold cross-session resume** is scheduled conservatively but its guess is NEVER persisted (`Posture.assumed`); an ERRORING resume with no `thread_id` is ambiguous → the thread is FORGOTTEN, not persisted with a guessed root.

**Lifecycle.** Worker→CC ids are remapped (workers all start their bridge ids at the same value); a remap entry dies with its owning call or its worker (tombstone → the pending CC dialog is cancelled, a late reply is swallowed). Park affinity: `codex_approve` routes home by token; the writable-root reservation OUTLIVES the parked call and is released on completion, on the **mirrored park cap** (engine-exact clamp), on worker death, or via the **liveness probe** — the engine also ends a park with NO MCP frame (inner-child death), and while parked it busy-blocks every tool except `codex_approve` with a distinct `codex turn parked` error, so a cheap `codex_info` answers "still parked or already gone". A retryable approve error (bad `decision_id` — the engine validates before `gen.send`) PRESERVES the park. A temp-cwd thread (writing sandbox, no `cwd`) pins its owning worker against reaping and its omitted-cwd resumes are routed back to that worker. Teardown closes worker stdin FIRST (their own #218/atexit paths), then terminate → kill.

## Architecture: codex MCP server (mcp/codex_server.py)

The bulldozer plugin ships its OWN MCP server (`mcp/codex_server.py`) — v2 as of 2026-06-19. Four tools (dispatched by `params.name` in `main()`): **`codex_run`** (turn lifecycle — review/implement), **`codex_info`** (connection-level reads — `query`: models/auth/config/limits/usage/servers/features/profiles/**approval** [the #277 unattended/park knobs + their source — purely local, no codex]; no cold-start), **`codex_review`** (native git-aware `review/start` — `target`: uncommitted/branch/commit/custom → free-text findings), **`codex_approve`** (#277 — resume a turn PARKED at an unattended approval; `{park_token, decision_id}`, no prompt/mcp). **Do NOT use the stock `codex mcp-server`** — see below. The `initialize` reply also carries an `instructions` routing manifest (`SERVER_INSTRUCTIONS` → `_initialize_result`, #256) — CC injects `InitializeResult.instructions` into the model's context on connect (CC #30135), giving a server-level map to pick between the tools (`codex_run`/`codex_info`/`codex_approve` are MCP-only — no skill covers them).

**V2 architecture** (replaced "wrap codex exec" v1): fronts `codex app-server` (bidirectional JSON-RPC over stdio — the same engine the Codex web app drives) for full interactive approvals, cross-session resume, and structured output:

- **Interactive approvals**: mid-turn command/file-change/permissions requests are bridged to CC via MCP elicitation (`elicitation/create`). Fixes codex#18268 where the stock MCP's Accept was mis-parsed as Denied. The elicitation wait is **human-paced (300s default**, threaded through `handle_server_request(..., timeout=)`); the turn deadline is **credited back** the approval wall-clock so a slow human Accept doesn't trip the opt-in `timeout` (when set) or the turn/start ACK setup window (F6). The `requestedSchema.label` enum carries **human-readable display strings** ("Allow once" / "Allow & always permit this command" / "Allow & always permit network access to `<host>` (`<action>`)" / "Cancel the turn" / "Grant for this session" / …) rendered as CC's dropdown; the chosen label is reverse-mapped back to the EXACT codex decision (string or amendment dict) so the #18268 fix stays intact (`LBL_*` constants + `build_command_approval_labels`; host+action carries primary distinctness for network labels, with `_dedupe_labels` as a last-resort numeric-suffix fallback that guarantees unique reverse-map keys). The enum is **OPTIONAL** — clicking CC's bare Accept (no dropdown selection) defaults to plain `accept`; a required field made CC block Accept with "This field is required" (live-UI bug, fixed). Both surfaced only via a real CC dialog (a programmatic driver answers instantly and never hits the 10s window or the form).
- **Resume**: `thread_id` arg resumes an existing non-ephemeral thread across sessions (cross-session via `~/.codex/sessions/` rollout files).

- **`codex_info` (2026-06-21):** connection-level reads via `AppServerManager.connection_request` (no thread/start, no cold-start) — REUSES the live child WITHOUT changing the isolation signature (never disrupts a warm `codex_run`). `_INFO_QUERY_MAP` maps `query`→method; `account/*` take no params, the rest take `{}`. Returns `{query, result}`. **`query="config"` is a compact whitelist projection** (`_CONFIG_OPERATIONAL_KEYS` + an `omitted` list of the other top-level keys; `origins` dropped) — raw `config/read` is ~71K and blows the MCP token limit (consult MINOR-FIXES; the `omitted` list keeps new codex keys visible, not silently hidden). Review output arrives as a **completed `agentMessage` item** (`.text`), NOT as deltas (verified live) — the pump collects `item/completed` agentMessage text when `_review_target` is set. `_parse_review_target`: `uncommitted`/`branch:<n>`/`commit:<sha>`/`custom:<text>`. **Latency profile (empirical, codex 0.141)**: the persistent `codex app-server` child is spawned once per session. The FIRST `thread/start` of a session pays a one-time cold-start cost that is **highly variable — ~28-80 s+ observed** (codex loads its setup regardless of the isolation flags; the spread depends on API/model-load conditions). Subsequent `thread/start` calls on the SAME alive process are warm (~1-2 s). `start_thread` (and `resume_thread`, since a cross-session resume is the first op on a fresh process) use a **180 s** `_pump_until` timeout to absorb the cold case — a 60 s ceiling intermittently timed out under real load (caught by a live MCP drive). The generous ceiling costs nothing on warm calls (it returns on the response).

**Permissions-grant semantics (#272)**: on accept, the `item/permissions/requestApproval` bridge echoes the codex-requested `RequestPermissionProfile` (`params["permissions"]`) into the response — granting exactly what codex asked for — with `scope` set per the chosen label (turn/session). A **bare** accept (no dropdown label) grants for the turn — CC's plain Accept — but an accept carrying an **unrecognized** label fails **closed** to `PERM_DECLINE` (`perm_map.get(chosen, PERM_DECLINE)`, with an `OUT_OF_ENUM_LABEL` drift note): the #272 grant-echo made the grant load-bearing, so an ambiguous label must not silently grant. The dialog renders the requested profile (`_summarize_permissions`, network first so the egress grant survives truncation of a large fileSystem list); a malformed non-dict `permissions` is not echoed (fail-open to `{}`). Request and granted profiles share the `{fileSystem?, network?}` shape (codex 0.141 schema), so the echo is structurally valid. (Pre-#272 the bridge granted an empty `{}` on accept — a silent no-op.)

**Approval-dialog localization — masking + provider chain (#247 + selector)**: the dynamic dialog text (codex's `reason` + the `Codex explained:` narrative — 1-2 plain prose strings) is OPT-IN translated into the user's language. `BULLDOZER_APPROVAL_LANG` (e.g. `ru`) turns it ON (default OFF → byte-identical English path). `_translate_texts` is a MASK→dispatch→RESTORE pipeline: `_mask_literals` swaps every path/backtick-command/quoted-literal/dotted-or-snake identifier for a `[N]` placeholder BEFORE translating, `_unmask_literals` restores them verbatim AFTER — empirically a translator MANGLES literals (`check`→`keck`, `git apply patch.diff`→`git applect.diff`), so for an approval dialog (where the user acts on what they read) literal fidelity outranks prose polish; masking ALSO keeps the literals out of any remote provider's egress (only the prose skeleton leaves the box) and raises the cache hit-rate (unique paths→`[N]`). `[N]` was the placeholder proven to survive OPUS-MT 3/3 (`<<N>>`/`«N»`/`__N__` get mangled). Two correctness guards (added under `bulldozer:check`): placeholder numbering starts ABOVE any `[N]` already in the input (collision-safe — the input's own bracketed tokens are never consumed/corrupted), and the dispatcher REJECTS any provider result that dropped/duplicated a placeholder OR has a malformed shape (`_placeholders_intact` + `isinstance(list)`/all-`str`/length checks) → falls through to the next provider / English, never accepting a corrupted literal and never crashing on a buggy provider. **Provider chain** via `BULLDOZER_TRANSLATE_PROVIDER` (`_translate_providers` → ordered list; unset → `['openai']` back-compat, `off` → disabled, else comma-list tried in order, each returns a list or None→next, all-fail→English): `google` = keyless raw `client=gtx` via stdlib `urllib` (`_translate_google`/`_google_http`, per-string, 1 retry on any transient failure, hard `_GOOGLE_TIMEOUT` 1.5s — best prose, zero new deps, but UNOFFICIAL: violates Google robots.txt/ToS + rate-limits on bursts, fine for the tiny opt-in volume); `opus` = offline OPUS-MT/CTranslate2 (`_translate_opus`/`_opus_engine`/`_opus_translate_one`, privacy-first ZERO-egress on-device, ~77MB int8 model, runtime needs ONLY `ctranslate2`+`sentencepiece` (NO torch/transformers) — **OPT-IN**: set `BULLDOZER_OPUS_MODEL_DIR` to an EXTRACTED CT2 model dir with `model.bin`+`source.spm`, e.g. an unzipped `ordois/opus-mt-en-ru-ctranslate2-int8`; `_opus_available` gates on `model.bin`+deps so a missing model fails-through cleanly); `openai` = the original LiteLLM/OpenAI-compatible path (`_translate_openai`, batched JSON via `_translate_cached`, also drives a local Ollama). **Recommended setup: `google,opus`** (Google primary, OPUS-MT on-device fallback, then English). OPUS gotcha (verified live): Marian REQUIRES a `</s>` EOS token appended to the source or it degenerates into a repetition loop that mangles the `[N]` placeholders. The provider registry maps name→attr-name resolved via `globals()` at call time (monkeypatch/hot-swap friendly). Failures are NEVER cached (each provider's own cache memoizes successes only). Knobs introspectable via `codex_info(query="approval")` → `translate_lang` + `translate_provider`.

**Dispatcher**: v2 `main()` and `cc_read_fn` both read CC frames through the module-singleton `_cc_stream` (class `CCStream`: `os.read` + `JsonRpcStream` into a queue) — NEVER `sys.stdin.readline()` (#264). `main()` blocks between turns with `next_frame(None)` (the first/only stdin reader) — EXCEPT while a turn is parked (#277), when it runs `_parked_wait` (a finite cap-bounded read that also pumps the child); `cc_read_fn` reads elicitation replies mid-turn with `next_frame(timeout)`; `Reactor.pump(watch_cc=True)` drains the SAME singleton — so `os.read` and `readline()` never mix on the fd, and a burst of frames in one CC write can't strand a 2nd frame in a `TextIOWrapper` buffer. `cc_write_fn` writes CC-facing JSON-RPC 2.0 frames (with `"jsonrpc":"2.0"`) to stdout; the app-server gets jsonrpc_lite frames (no `"jsonrpc"` key) — asymmetric by design.

**Module singleton**: `_v2_manager` (AppServerManager) + `_v2_state_machine` (TurnStateMachine) are module-level singletons — ONE ENGINE PROCESS runs one turn at a time. The serial dispatcher loop is the primary concurrency protection (MCP calls arrive one at a time); the busy guard (`TurnStateMachine.is_busy()` → `codex turn already in flight`) is defense-in-depth. **Since 2026-07-18 the registered server is the FACADE** (`.mcp.json` → `codex_facade.py`, § above), which fronts a lazy pool of these engine processes — the singleton constraint is per-WORKER, and concurrent turns through the ONE registration genuinely overlap (wall = max, not sum). **Fan-out = one call per SUBAGENT** (sonnet or stronger — haiku fumbles MCP tool calls after ToolSearch): subagents share the session's one connection per registration (no per-subagent spawn), and the facade multiplexes behind it; keep a run→approve loop inside one subagent (`codex_approve` routes the park token home through the same registration). What still serializes: (a) **multiple UNHINTED MCP calls issued in ONE assistant message** — CC dispatches them serially (empirically session `04ad23aa`, 2026-06-21: 294 s + 200 s back-to-back = sum, not max); the EXCEPTION is `readOnlyHint`-annotated tools — `codex_review`/`codex_info` carry the hint (facade `tools/list`, § above), and CC 2.1.214 dispatches same-message hinted calls in PARALLEL (verified 2/2 vs 2/2 serial control) — so main-session review fan-out from one message works; `codex_run`/`codex_approve` stay serial-per-message; (b) approval-capable turns (effective `approval_policy != "never"`) and overlapping writable roots — they queue (`FACADE_QUEUED`) by design; `codex_review` is always parallel-class. **Auto-background (CC ≥ 2.1.212, verified 2026-07-17):** an MCP call still running at ~120 s is auto-backgrounded into a task (returns via task-notification; `TaskStop` cancels; does NOT survive session exit — verified with a 158 s `codex_run` through the facade). Consequence: the MAIN session can STACK long turns one per message — each holds the session ~120 s before backgrounding, a 120 s-stagger slow lane; calls finishing under ~120 s block their message; **subagent calls are NEVER auto-backgrounded** — subagents remain the instant fan-out mechanism. Writable fan-out needs FILESYSTEM isolation too (`mcp:'isolated'` does not isolate the FS): omit `cwd` (per-turn isolated tmpdir) or one worktree per job — two workspace-write turns into one checkout race it (and the facade serializes overlapping writable roots anyway); parallel jobs against a single checkout stay read-only. **Lane pool is HISTORICAL** (2026-07-13: N named registrations of the engine proved wall = max with 102 s overlap; lanes and the stock `codex mcp-server` registration were REMOVED — superseded by the facade; stock remains only a wider-than-pool fallback and carries the #18268 approval bug ⇒ read-only, `approval-policy: never`). Other alternatives: background CLI `codex exec`, or distinct CC sessions. NB: a local `claude mcp add` registration of this same server **suppresses the plugin's own server** in that project (CC marks it `excludeStalePluginClients`; observed 3/3 sessions) — fine in the dev project, where it serves the same four tools from SOURCE (fresher than the cache); consumer configs carry no local registrations and keep the plugin server. `.mcp.json` = `{"codex": {"command": "python3", "args": ["${CLAUDE_PLUGIN_ROOT}/mcp/codex_facade.py"], "env": {}}}`. The server requires **Python 3.11+** (`tomllib` in the engine; the facade spawns workers with its own `sys.executable`); since that bare `python3` may resolve to an older interpreter, the engine's startup guard (`_python_version_error`) fails loud with a clear stderr message instead of a cryptic `ModuleNotFoundError: tomllib` (#256).
