Почему bundled, а не npx (твой инцидент: 38 серверов · 3.8 ГБ)

✗ npx / uvx @latest

  • ре-резолв пакета на каждый старт (15–30с, в облаке сервер молча дропается)
  • version drift — @latest тянет что попало
  • cache bloat: uvx datahub@latest → 3765 venv ≈ 150 ГБ
  • supply-chain риск (litellm PyPI-компромет), Windows spawn ENOENT

✓ bundled-local (uv run --frozen, self-sync venv)

  • депы живут в ${CLAUDE_PLUGIN_DATA}/.venv, наполняются на первом старте (uv сверяет lock↔venv локально — #217, НЕ SessionStart-hook)
  • запуск: uv run --frozen server.py → self-sync из committed lock, ноль дрейфа
  • reuse проверенного gemini_files.py из goat (TDD+bulldozer+E2E)
  • video-сервер idle-дёшев: нет upstream-соединения (в отличие от channel-плагина)
Ключевое отличие от channel-боли: те плагины плодили RAM, потому что держали постоянное соединение (Matrix /sync, web-порт). Video-сервер спит на stdin и просыпается только на вызов → «38 серверов 3.8 ГБ» структурно не грозит.
