# Gemini `mediaResolution` — эмпирические токен-затраты (verified by probe, NOT docs)

> Замер **2026-06-19**, `reference/probe_mediaresolution.py`, реальный `promptTokenCount`
> из `usageMetadata` на двух видео (conv.mp4 45с реальный RU-разговор; video_with_audio.mp4 24с синтетика).
> **Источник истины = ЭТОТ замер, не docs.** Google-доки про 2.5 ОПРОВЕРГНУТЫ (заявляли «2.5 HIGH=256,
> medium=70» — реальность другая: см. ниже). Токены детерминированы (n=1 надёжно); латентность — медиана 3
> прогонов на free-tier (шумная, иллюстративна).

## Видео-токены на кадр (семплинг 1 fps по умолчанию)

### Gemini 2.5-flash
| res | ток/кадр | conv.mp4 45с VIDEO | synth 24с VIDEO | латентность conv |
|------|----------|--------------------|------------------|------------------|
| LOW | **≈71** | 3195 | 1704 | 5.5с |
| MEDIUM | ≈263 | 11835 | 6312 | 7.1с |
| HIGH | ≈263 | 11835 | 6312 | 9.5с |
| default (unset) | ≈263 | 11835 | 6312 | 9.6с |

**На 2.5 `default` = `MEDIUM` = `HIGH` (идентичны по токенам).** Экономит только `LOW` (3.7× меньше).
AUDIO выносится отдельной модальностью: 1440 ток (45с) / 768 ток (24с) ≈ **32 ток/с** (как в docs).

### Gemini 3.5-flash (стабильная) и 3-flash-preview
| res | ток/кадр | conv.mp4 45с VIDEO | латентность 3.5-flash |
|------|----------|--------------------|------------------------|
| default | **≈85** | 3825 | 2.6с |
| LOW | ≈85 | 3825 | 2.3с |
| MEDIUM | ≈85 | 3825 | 2.1с |
| HIGH | **≈289** | 13005 | 8.5с |

**На 3.x `default` = `LOW` = `MEDIUM` (дёшево); `HIGH` в ≈3.4× дороже.** AUDIO свёрнут в VIDEO-токены
(`promptTokensDetails` без AUDIO-строки — это НЕ глухота, см. AGENTS.md taxonomy).

## Ключевые правила (то, ради чего файл существует)

1. **`mediaResolution` ИНВЕРТИРОВАН по семействам моделей:**
   - **2.5:** HIGH «бесплатен» относительно дефолта (те же токены) → +качество почти даром; экономит только `LOW`.
   - **3.x:** HIGH — дорогой спец-инструмент (3.4×), нужен ТОЛЬКО для OCR/мелкого текста; дефолт уже дёшев.
   - Одно правило на оба семейства написать НЕЛЬЗЯ. При смене дефолтной модели — **перезамерить probe**.

2. **Модель — самый большой рычаг скорости/стоимости.** 3.5-flash default (3825 ток / ~2.5с) против
   2.5-flash default (11835 ток / ~9.6с) на ОДНОМ файле = **≈3× дешевле и быстрее**. И 3.5-flash стабильна.

3. **«MEDIUM vs HIGH на 2.5 ускорит» — МИФ.** Они идентичны. Реальные рычаги скорости ниже.

## Рычаги скорости видео (по убыванию эффекта)

1. **Модель** — 3.x default ≈3× дешевле 2.5 default на видео-токенах.
2. **Длина видео** (линейно по кадрам) → `prepare_media` trim. (Объясняет «293MB/164с медленно».)
3. **fps ↓** (param `fps`) — меньше кадров; для статичных лекций 0.5 fps вдвое режет.
4. **`mediaResolution=LOW`** — только на 2.5 (3.7× меньше видео-ток); на 3.x LOW=default (не помогает).

## Воспроизвести

```bash
cd server && GEMINI_API_KEY=... \
  JAINE_PROBE_MODELS="gemini-2.5-flash,gemini-3.5-flash" \
  uv run --no-sync python ../reference/probe_mediaresolution.py
```
`JAINE_PROBE_ONEFILE=1` — только conv.mp4. Probe переиспользует наш upload+диск-кэш (`get_or_upload`).
conv.mp4 — локальный пример (gitignored); `reference/video_with_audio.mp4` воспроизводим из репо.
